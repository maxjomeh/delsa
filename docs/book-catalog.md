# کاتالوگ مشترک کتاب (Delsa Books، فاز ۳-ب)

**وضعیت:** نوشته و تست‌شده روی Postgres محلی. **روی دیتابیس production اعمال نشده است** و بدون تأیید صریح اعمال نمی‌شود.

## مدل داده

```
book_works (اثر) ──< book_work_people (نویسنده) >── book_people
      │
      └─< book_editions (نسخه: ISBN13، عنوان، ناشر، سال، چاپ، صفحه، جلد، تصویر، منبع، تأییدشده؟)
              ├── book_publishers
              └─< book_edition_people (مترجم، مصور، ویراستار) >── book_people

builder_product_books : محصول یک فروشگاه ──> یک نسخه‌ی کاتالوگ  (قیمت، موجودی و توضیحات در خود محصول می‌مانند)
book_isbn_lookup_log  : سقف نرخ جست‌وجوی بیرونی (خصوصی)
```

- کاتالوگ فقط **واقعیت‌های کتاب‌شناسی** دارد. هر قیمت، موجودی یا متن اختصاصی در `builder_products` هر مشتری می‌ماند؛ داده‌ی مشتری‌ها با هم ادغام نمی‌شود.
- یک **اثر** چند **نسخه** دارد (چند ناشر، چند ترجمه، چاپ‌های مختلف). اثر با «عنوان نرمال‌شده + نویسنده‌ی اول» شناسایی می‌شود.
- نرمال‌سازی فارسی (`fa_norm`): ي/ك عربی، رقم‌ها، اعراب، کشیده و نیم‌فاصله یکسان می‌شوند. اعتبار ISBN-10/13 در `book_isbn13` بررسی می‌شود. هر دو معادل JS در `lib/book-isbn.js` دارند و تست parity آن‌ها را مقایسه می‌کند.

## قواعد دسترسی

| کاربر | می‌تواند |
|---|---|
| همه (anon) | خواندن کاتالوگ (بدون ستون‌های `created_by` و `verified_by`)، `catalog_lookup_edition`، `catalog_search`، دیدن پیوندهای سایت‌های منتشرشده |
| مشتری دارای دسترسی سایت‌ساز | `catalog_upsert_edition` (نسخه‌ی تازه با نشان «تأییدنشده»؛ هرگز بازنویسی نسخه‌ی موجود)، `catalog_register_lookup`، پیوند دادن محصول **خودش** به نسخه |
| مدیر | تأیید و اصلاح نسخه‌ها، نسخه‌های تأییدشده، منبع `national_library` |

- نوشتن مستقیم در جدول‌های کاتالوگ برای مشتری بسته است؛ فقط RPC با اعتبارسنجی کامل.
- سقف‌ها: ۳۰۰ نسخه‌ی جدید در روز و ۶۰ جست‌وجوی بیرونی در ساعت برای هر کاربر.
- هر نسخه `source`، `source_ref` و `field_sources` دارد (هر فیلد از کجا آمده).

## منبع بیرونی

فقط **Open Library** (`lib/book-lookup.js`): پاسخ فقط یک **پیشنهاد** است و مشتری پیش از ذخیره آن را تأیید یا اصلاح می‌کند. محدودیت‌ها: مهلت ۴ ثانیه، حداکثر ۲۰۰ کیلوبایت، تصویر فقط HTTPS از Open Library، طول فیلدها محدود. منابع دیگر (Google Books، کتابخانه‌ی ملی، فروشگاه‌ها) تا بررسی حقوقی شرایط استفاده اضافه نشده‌اند.

## اجرای تست‌ها

```bash
supabase/tests/local-postgres/run.sh        # SQL، parity و rollback روی Postgres موقت
node supabase/tests/book-isbn.test.cjs      # ISBN، نرمال‌سازی، Open Library (بدون شبکه)
```

`run.sh` یک خوشه‌ی موقت Postgres می‌سازد، لایه‌ی سازگاری Supabase (`shim.sql`) و فایل‌های SQL موجود پروژه را اعمال می‌کند و بعد تست‌ها را می‌دوانَد. تست‌های SQL موجود (`site-builder-access`، `builder-commerce`) هم روی همین محیط پاس می‌شوند:
`supabase/tests/local-postgres/run.sh supabase/tests/site-builder-access.sql`.

## اعمال روی production (پس از تأیید)

1. پروژه‌ی Supabase مربوط به delsaai را در SQL Editor باز کنید (یا با کانکتور Supabase).
2. `supabase/book-catalog.sql` را یک بار اجرا کنید (افزونه‌ی `pg_trgm` لازم است و در Supabase در دسترس است).
3. `supabase/tests/book-catalog.sql` را اجرا کنید (همه‌چیز را rollback می‌کند؛ به دو حساب عادی و یک مدیر نیاز دارد).
4. بازگشت: `supabase/book-catalog-rollback.sql`.

## هنوز انجام نشده (۳-ج)

ادغام در فرم محصول (دکمه‌ی جست‌وجوی ISBN و تأیید دستی)، ورود گروهی CSV، صفحه‌های نویسنده و ناشر، SEO کتاب (JSON-LD)، و رابط مدیر برای تأیید نسخه‌ها.
