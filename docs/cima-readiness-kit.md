# کیت آمادگی داده‌ی واقعی سیما (فاز ۶)

هدف: بدون اتصال هیچ سرویسی به مخزن، روی گفت‌وگوهای واقعی خودتان بفهمید سیما کدام موضوع‌ها را پیدا می‌کند، کجا پاسخ تأییدشده ندارد و هر موضوع به‌طور تخمینی تا کدام مرحله می‌تواند برسد.
این کیت فقط **می‌خواند و گزارش می‌دهد**؛ چیزی نمی‌فرستد، به جایی وصل نمی‌شود و در پایگاه‌داده چیزی نمی‌نویسد.

## مراحل

1. فایل `supabase/exports/cima-readiness-export.sql` را در SQL Editor سوپابیس باز کنید.
2. در بخش `params` فقط یک مقدار را عوض کنید: شناسه‌ی tenant (همان `profiles.id` مشتری). بازه‌ی پیش‌فرض ۱۸۰ روز و سقف پیش‌فرض ۲۰٬۰۰۰ ردیف است.
3. اجرا کنید و خروجی JSON را در یک فایل (مثلاً `export.json`) ذخیره کنید.
4. ابتدا بررسی حریم خصوصی:

```bash
node scripts/cima-readiness.mjs --input export.json --audit
```

5. اگر `audit: ok` بود، گزارش را بسازید:

```bash
node scripts/cima-readiness.mjs --input export.json --out report.md
```

برای خروجی ماشین‌خوان از `--format json` استفاده کنید.

## چه چیزی خارج می‌شود و چه چیزی نه

- فقط دو جدول خوانده می‌شود: `crm_interactions` (پیام‌های ورودی/خروجی از نوع `message`) و `sima_knowledge_entries` (فقط ورودی‌های تأییدشده)، هر دو فقط برای همان tenant.
- شناسه‌ها با `md5(id || tenant)` یک‌طرفه می‌شوند؛ نام، تلفن، نام کاربری اینستاگرام، توکن و اعتبارنامه اصلاً خوانده نمی‌شوند.
- متن پیام تا ۶۰۰ نویسه بریده می‌شود و ایمیل، لینک، @آیدی و رشته‌ی عددی بلند (۸ نویسه یا بیشتر) با `[ایمیل]`، `[لینک]`، `@[آیدی]` و `[عدد بلند]` جایگزین می‌شود.
- ماسک‌کردن بر اساس الگوست و کامل نیست (مثلاً نام افراد داخل متن آزاد حذف نمی‌شود). به همین دلیل `--audit` همیشه اجرا می‌شود و گزارش هرگز متن شخصی را چاپ نمی‌کند؛ فقط نوع و محل یافته را می‌گوید. قبل از اشتراک‌گذاری فایل، خودتان هم نگاهی بیندازید.
- گزارش خروجی هم به‌طور پیش‌فرض ماسک می‌شود؛ `--no-redact` آن را خاموش می‌کند و در گزارش هشدار می‌نویسد.

## گزارش چه می‌گوید

- **خلاصه**: تعداد جفت‌های پرسش و پاسخ، سهم موضوع‌های «فقط انسانی» (قیمت، شکایت، پرداخت و…) و موضوع‌های کاندید خودکار.
- **موضوع‌ها**: برای هر موضوع تعداد نمونه، پوشش پاسخ تأییدشده، نرخ ردشدن، اعتماد اندازه‌گیری‌شده و مرحله‌ای که تخمیناً می‌تواند برسد.
- **کارهای پیشنهادی** به ترتیب اولویت: نوشتن پاسخ استاندارد، رفع ابهام بین دو پاسخ، بازبینی پاسخ‌هایی که با گفتار واقعی فرق دارند، افزودن متغیرهای پرسش، تعریف فیلدها و فعال‌سازی.

## محدودیت‌ها (صادقانه)

- مرحله‌ی «قابل‌دستیابی» یک **پیش‌بینی** از تاریخچه است، نه وعده. شرط‌های زنده (کلید خودکار سرور، تأیید مالک، سقف‌ها، پنجره‌ی ۲۳ ساعته) جداگانه بررسی می‌شوند.
- این کیت تا امروز روی داده‌ی ساختگی و یک Postgres موقت آزموده شده، نه روی گفت‌وگوهای واقعی مشتری.
- نتیجه به کیفیت دسته‌بندی متن فارسی (واژه‌ها و سه‌نویسه‌ها) وابسته است؛ موضوع‌های پیدا‌شده را قبل از فعال‌سازی ببینید.
